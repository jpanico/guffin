# CLAUDE.md

## Project Overview
Python 3.14 toolkit for exporting Roam Research pages to self-contained
documents.  Supports three output formats:

- **Markdown** — renders to GFM and optionally bundles Cloud
  Firestore-hosted images and PDFs into a self-contained `.mdbundle` directory.
- **PDF** — builds a Pandoc object model directly from the `VertexTree`
  via Panflute, fetches and embeds Cloud Firestore images and PDF assets
  (attached originals; optionally inline-rendered pages), and produces a
  PDF via Pandoc + Typst (the bundled Bergfink template).
- **EPUB** — builds the same Pandoc object model and produces an EPUB 3
  e-book via Pandoc, with images embedded into the package.

Orthogonal to the format, a **project type** (`default`/`book`/`manuscript`,
CLI `--type`) says what *kind* of work is being produced; its structural
policy drives title page, heading numbering, chapter/part pagination, and
preamble handling in the paginated formats.  Document structure and
bibliographic metadata are declared in the Roam content itself through the
format-independent `guffin`-domain attribute vocabulary (`guffin-meta::`
metadata, `element-type::`/`matter::` heading tags), which each renderer
maps to its format's own conventions.

Both commands are also servable remotely: **server mode** (`guffin-server`,
the `server/` sub-package) exposes `dump-roam-tree` and `export-roam-tree` as
HTTP command endpoints — the JSON Request mirrors the CLI arguments, and the
response carries the exported document (integrity-headed, streamed) or the
captured dump rendering — so any machine can request work from the one
running Roam Desktop, the only host the Roam Local API answers on; see
`docs/server-mode.md`.

## Key Commands
```bash
dump-roam-tree <page_title_or_node_uid> -p <port> -g <graph> -t <token> [-v/-V] [-n/-N] [-r/-R] [--show-transient/--no-show-transient] [--verify-code-sources/--no-verify-code-sources] [--node-props <props>] [--cache-dir <dir>] [--version]
export-roam-tree <page_title_or_node_uid> -p <port> -g <graph> -t <token> -o <output_dir> [--format markdown|pdf|epub] [--type default|book|manuscript] [--bundle|--no-bundle] [--cache-dir <dir>] [--template-dir <dir>] [--suppress-attributes] [--colophon|--no-colophon] [--preamble|--no-preamble] [--numbering|--no-numbering] [--element-numbers|--no-element-numbers] [--code-sources|--no-code-sources] [--verify-code-sources|--no-verify-code-sources] [--daily-note-format roam-long|iso|abbrev-month-day] [--version]
# output filename stem embeds the project type: <target>.<type>.<ext> (e.g. Foo.default.epub, Foo.book.pdf)
# --format markdown (default): writes <target>.<type>.mdbundle/ (--bundle) or <target>.<type>.md (--no-bundle)
# --format pdf: writes <target>.<type>.pdf via Pandoc + Typst; requires typst on PATH
# --format epub: writes <target>.<type>.epub (EPUB 3) via Pandoc; requires pandoc on PATH (no typst)
# --type (-T): project profile (default/book/manuscript); appended to the output filename stem; plumbed to all renderers (all six structural directives applied in the paginated formats — top_level_division, number_sections, emit_title_page, emit_toc, drop_preamble, honor_page_breaks — plus bibliographic metadata from a root page's guffin-meta:: attributes; markdown expresses emit_title_page as a YAML front-matter block carrying the document metadata, the title both there and as the leading H1)
# a heading tagged page-break:: before (a guffin-meta:: child of the heading) opens on a new page in the paginated formats — honored for default/manuscript projects; a book's pagination is fixed by its own structure, so a book export drops the tag with a warning (StructuralPolicy.honor_page_breaks)
# --preamble/--no-preamble (pdf/epub only): keep or drop the export root's loose preamble (children before its first heading); unset, the --type profile decides (book drops, others keep)
# --numbering/--no-numbering (pdf/epub only): turn all heading numbering on or off; unset, the --type profile decides (book numbers, others don't)
# --element-numbers/--no-element-numbers (all formats): keep or strip internal element numbers (a heading's bracketed dotted lead, e.g. [1.2.3]) in the exported document; default strips them (they are authoring bookkeeping, not content) — dump-roam-tree always shows them
# --code-sources/--no-code-sources (all formats): render or omit each sourced code block's GitHub attribution line (from its code-source:: tag) below the listing; default omits (the attributions are authoring metadata) — enabled, the line links the github.com blob page pinned at the recorded commit SHA
# --verify-code-sources/--no-verify-code-sources (both commands; default ON): verify every code-source::-tagged code block against GitHub — resolve the URL's ref to its tip commit via api.github.com (GUFFIN_GITHUB_TOKEN raises the rate limit; SHA refs skip the API), fetch the immutable SHA-pinned raw content, slice the line range, and compare; findings (drift vs local-modification, disambiguated via the recorded snapshot SHA, or fetch-failure) abort an export with exit 1, but are advisory warnings in dump-roam-tree (the dump always renders) — --no-verify-code-sources is the offline escape hatch
# --daily-note-format (all formats): how a reference/link to a Roam daily-note page renders its date — roam-long (default; the page's own verbose title, e.g. January 1st, 2026, so output is unchanged), iso (ISO 8601, e.g. 2026-01-01), or abbrev-month-day (abbreviated month + day, no year, e.g. Jan 1)
# a book auto-detects parts from its content (cli/common.resolve_profile): any level-1 heading tagged element-type:: part switches the book to the PART division — chapters live at level 2, the EPUB splits files at level 2, and the PDF opens both parts and chapters on a new page; a root-level section of explicit front/back matter (e.g. a level-2 About the Author tagged matter:: back-matter after the last part) is promoted to part level in every format so ToCs never nest it under the preceding part
# a {{[[pdf]]: <url>}} embed is content-tag controlled: pdf-render:: (a guffin-meta:: child of the embed block) declares where its pages go and at what fidelity — inline-native/inline-image at the embed, appendix-native/appendix-image in an appendix at the back linked from the embed — or that the file itself is referenced rather than reproduced: internal-link (a copy travelling inside the output), external-link (the hosted original), name-only (the filename as plain text). The tag may equally sit on a standalone block reference to the PDF (the reference site's tag governs that reference and outranks the target embed's own tag, since the site is where this document displays the PDF). An untagged embed's placement depends on the output — format, --bundle mode, and --type (render/pdf_placement.default_pdf_render) — and any placement a format cannot honor falls back to name-only with a WARNING, so a request is never silently dropped. Only inline-native (pdf, via typst >= 0.14), internal-link (markdown --bundle), external-link, and name-only are implemented today; see docs/pdf-render.md
# --template-dir: directory containing user_cfg.typ overrides for PDF styling (pdf only)

guffin-server [--host <addr>] [-p <port>] [--version]
# serves both commands as HTTP command endpoints on 127.0.0.1:8077 by default — POST /v1/export (the exported
# document; a .mdbundle answers zipped, with Content-Length/Content-Digest/Content-Disposition), POST /v1/dump
# (the captured console rendering; console_format text/html/svg), GET /v1/health; request fields mirror the CLI
# args (omitted fields fall back to the server-side GUFFIN_* env), errors answer RFC 9457 problem+json; must run
# on the machine running Roam Desktop; see docs/server-mode.md

# Run the full check pipeline (format + lint + type check + tests) in one shot.
# The test step is `test-heavy`, so live tests run too — requires Roam Desktop running locally:
hatch run check

# Individual steps (run in this order):
pydocstringformatter --write src/ # reflow docstring content (PEP 257)
black .                           # format code
ruff check --fix src/ tests/      # lint + fix docstring style (Google convention)
pyright                           # type check (strict)
pytest                            # run tests (excludes live tests)

# Test tiers (defined as hatch scripts in pyproject.toml), lightest to heaviest:
hatch run test-light   # skips pandoc-subprocess-bound integration tests (marked `pandoc`); the fast inner loop (~2.5s)
hatch run test-medium  # the full offline suite
hatch run test-heavy   # everything, live tests included; requires Roam Desktop running locally; the tier `check` runs

# Live tests only, directly (requires Roam Desktop running locally):
GUFFIN_LIVE_TESTS=1 pytest -m live -v
```

## Project Structure
- `src/guffin/` — main package
  - **`cli/` sub-package** (`src/guffin/cli/`) — CLI entry points and supporting infrastructure
    - `dump_roam_tree.py` — dumps a Roam page or node subtree as a Rich tree to the terminal; supports `--render-bundle`/`--node-tree`/`--raw-results` flags, plus `--show-transient` to include the transient session/UI attribute columns (hidden by default) in the raw-results table, and `--cache-dir`/`-c` (env `GUFFIN_CACHE_DIR`) to cache across runs the assets the render-bundle view fetches for its enrichment (`dump-roam-tree`). The `--render-bundle` (`-b`) view renders both parts of the `RenderBundle`: an outer panel over a `Vertex Tree` sub-panel (the content `VertexTree`) followed by a `View Map` sub-panel (the presentation `ViewMap`, as a tree of only the vertices carrying a view entry plus the ancestors linking them to the root, each panel titled like its vertex panel and bodying its `VertexView`)
    - `export_roam_tree.py` — exports a Roam page or node subtree; `--format markdown` (default) writes a `.mdbundle` or plain `.md`; `--format pdf` writes a PDF via Panflute + Pandoc + Typst; `--format epub` writes an EPUB 3 e-book via Panflute + Pandoc; target is a page title or node UID (`export-roam-tree`)
    - `serve.py` — launches the HTTP server front end (`guffin-server`): starts uvicorn on the `server/app.py` ASGI app; `--host`/`--port` (env `GUFFIN_SERVER_HOST`/`GUFFIN_SERVER_PORT`), binding `127.0.0.1:8077` by default — the sole `cli/` module allowed to import `server/`
    - `logging_config.py` — colorized logging (`configure_logging()`); reads `LOG_LEVEL` env var
    - `params.py` — the Typer parameter declarations shared across the CLI commands: `TargetArgument` (the page-title-or-node-UID positional), the Local API options `PortOption`/`GraphOption`/`TokenOption`, `CacheDirOption`, and `VersionOption` (`--version` — an eager print-package-version-and-exit callback, taken by all three commands), each bundling the parameter's type with its `Argument`/`Option` metadata (flags, env var, help) so one declaration serves every command that takes it (a per-command default is still supplied at the call site); each alias is a plain `Name = Annotated[...]` assignment, never a PEP 695 `type` alias, because Typer reads the embedded metadata off the annotation object and cannot see through a `TypeAliasType`
    - `code_source_verification.py` — the effectful half of code-source verification (Typer-free, like `common.py`; homed in `cli/` beside its sole consumer until a second, non-CLI consumer forces a promotion — the package root deliberately stays module-free, enforced by `tests/test_architecture.py`): gathers the source-of-truth evidence (ref resolution + SHA-pinned content via `common/github_fetch.py`, line narrowing via `common/line_range.py` — the snapshot-commit fetch happens only when the judgment needs disambiguation) and hands it to the pure verdict in `model/code_source_diagnosis.py`, mapping any retrieval error to a `FETCH_FAILURE` finding: `verify_code_source()` (one block) and `verify_code_sources()` (every sourced, render-visible code block, returning all accumulated `CodeSourceFinding`s — the caller decides severity, mirroring `validate_semantics`: `cli/common.fetch_roam_trees` runs it as the fetch pipeline's second gate when `verify_code_sources=True`, so `export-roam-tree` aborts with exit 1 on any finding while `dump-roam-tree` reports findings as advisory warnings; both via `--verify-code-sources`, default on)
    - `common.py` — tree-loading pipeline for CLI commands; `fetch_roam_trees` resolves a target, fetches nodes, and returns a `(NodeFetchResult, VertexTree | None)` pair, running the pipeline's content gates on the transcribed content: `validate_semantics` always, and the networked code-source verification (`code_source_verification.verify_code_sources`) when called with `verify_code_sources=True`. Each gate's findings are handled per the caller's `strict` posture — logged as warnings (default), or raised as `SemanticsValidationError` / `CodeSourceVerificationError` (`strict=True` — export's posture; dump stays advisory); `resolve_profile` builds the `ProjectProfile` for a project type, refined by the content (a book with part-tagged level-1 headings becomes a parts book); every vertex-tree fetch also captures the content `Revision` (snapshot hash from the raw wire response via `roam/revision.gather_revision`, revision name from the root's authored `revision::` attribute) onto the returned bundle
  - **`server/` sub-package** (`src/guffin/server/`) — HTTP server front end: remote RPC-like invocation of the two CLI commands (design + decision log in `docs/server-mode.md`)
    - `app.py` — the FastAPI ASGI application: `POST /v1/export` answers the exported document as a streamed binary body (a `.mdbundle` answers zipped) with `Content-Length` + RFC 9530 `Content-Digest` + `Content-Disposition`; `POST /v1/dump` answers the captured console rendering in the requested representation; `GET /v1/health` answers liveness + version + provenance. Bodies validate against the derived request models (`400` problem on failure), a failed invocation answers `422` with an RFC 9457 problem body whose `detail` carries the complete captured error text (log records + stderr + traceback), a serving-layer fault answers `500`, and invocations serialize behind a process-wide lock; the response begins only after the invocation fully completes (render-then-send)
    - `request_derivation.py` — derive a wire-request vocabulary from a Typer command signature, so the CLI declaration stays the single source of truth: `RequestField`/`RequestFieldKind`, `request_fields_for()` (one field per parameter, in signature order), `derived_request_model()` (Pydantic model; non-positional fields optional with a `None` default so an omitted field defers to Typer's own resolution, env-var fallbacks included; `extra="forbid"`), `argv_for_request()` (deterministic Request→argv translation, long flag spellings preferred; mirrors Typer's Annotated-usage reading where `typer.Option`'s first positional lands in the `default` slot)
    - `request_models.py` — the concrete derived models, built at import time: `EXPORT_REQUEST_MODEL`/`EXPORT_REQUEST_FIELDS` (excludes `output_dir` — the server allocates a per-request temp output dir) and `DUMP_REQUEST_MODEL`/`DUMP_REQUEST_FIELDS` (plus the serving-layer console extras `console_format`/`console_width`/`ansi`, which never translate to argv); both vocabularies exclude the CLI-only `version` flag (a terminal print-and-exit affordance — the health endpoint reports the serving package's version)
    - `invocation.py` — in-process command invocation with structured capture: `invoke_typer_command()` runs a Typer app through `CliRunner` (Typer's own parsing/defaults/env fallbacks, no subprocess) and returns an `InvocationResult` (exit code, stdout, stderr, every log record via a swapped-in root handler, formatted traceback); the process-global swaps are why the caller must serialize invocations
    - `console_export.py` — the representation a captured console rendering is returned in: `ConsoleFormat` (`text`/`html`/`svg`), `CONSOLE_MEDIA_TYPE`, `console_environment()` (the `COLUMNS`/color env overlay a capture runs under), `exported_console()` (ANSI capture → verbatim text, or re-rendered via Rich `Text.from_ansi` → `export_html`/`export_svg`)
    - `export_artifact.py` — the artifact an export leaves in its output directory, packaged for transfer: `resolved_artifact_path()` (the single artifact entry; debug files ignored; zero or many is an error), `packaged_artifact()` (`.mdbundle` directory → zip beside it, layout preserved), `content_digest_header()` (RFC 9530 `sha-256` value), `ARTIFACT_MEDIA_TYPES`
    - `problem_details.py` — RFC 9457 problem-details responses: `PROBLEM_MEDIA_TYPE`, `problem_response()`
  - **`model/` sub-package** (`src/guffin/model/`) — core normalized-graph model: UID primitives, vertex types, tree, presentation overlay, render bundle, and inter-vertex links
    - `primitives.py` — foundational UID primitives for the model: `Uid`, `SYNTHETIC_UID_PATTERN`/`DAILY_NOTE_UID_PATTERN`/`UID_PATTERN`/`UID_RE`, `ANCHORED_UID_PATTERN`/`ANCHORED_UID_RE`, `is_daily_note_uid()` (dependency root)
    - `vertex.py` — `VertexType` StrEnum classifying each vertex by the shape of its source `RoamNode` (`PAGE`/`TEXT`/`HEADING`/`IMAGE`/`PDF`/`CALLOUT`/`CODE_BLOCK`/`QUOTE_BLOCK`/`TABLE`/`BLOCK_EMBED`/`PAGE_EMBED`); the `Vertex` union and all eleven concrete vertex types (`PageVertex`, `HeadingVertex`, `TextVertex`, `ImageVertex`, `PdfVertex`, `CalloutVertex`, `CodeBlockVertex`, `QuoteBlockVertex`, `TableVertex`, `BlockEmbedVertex`, `PageEmbedVertex`); the `QuoteType` StrEnum (`BLOCK`/`PULL` — a quote block's source-agnostic rendering intent) and the `QuoteBlockVertex` produced from any of the three Roam quote forms (a standard Markdown `> ` quote, a Roam-native `[[>]]` quote — both `QuoteType.BLOCK`, a plain block quote — or a Roam `[[>]] [[!QUOTE]]` pull quote — `QuoteType.PULL`, the decorated quotation+attribution treatment), carrying `quote_type`, `quote`, and an optional `attribution` (pull quotes only; the transcriber maps the source marker to the `QuoteType` and splits quote/attribution at that boundary; `CalloutType` has no `quote` member); the `PageVertex.daily_note_date` field (the `datetime.date` a page represents when its `uid` is an `MM-DD-YYYY` daily-note date, else `None`; set once at transcription, letting a renderer format daily-note references by date rather than the Roam-authored title); the `CodeBlockVertex.code_source` field (the optional `model/code_source.CodeSource` provenance of a snapshotted code listing, set at transcription from a `code-source::` tag); the shared `_BaseVertex.attribute_assignments` field holding folded Roam attribute assignments (`<attribute>:: <value>, …`); `find_attribute_assignment()` looks up a vertex's folded assignment for an `Attribute` (delegating to `attribute.find_assignment_for()`); the `AssetVertex` union of the asset-bearing vertex types (`ImageVertex | PdfVertex` — content is a Cloud Firestore-hosted file, not inline text; the union is the single source of truth for asset-bearing-ness) with its narrowing predicate `is_asset_vertex()` (checks against a runtime tuple derived from the union itself); the `EmbedVertex` union of the transcluding vertex types (`BlockEmbedVertex | PageEmbedVertex` — content is the EMBED-linked target reproduced at the embed site; same single-source-of-truth pattern) with its narrowing predicate `is_embed_vertex()`; `VertexChildren`, `VertexRefs`, `vertex_adapter`
    - `vertex_tree.py` — `VertexTree`, `VertexTreeDFSIterator`, `root_vertex()`; `transcluded_vertices()` (the render-visible vertices: tree vertices plus embed-transcluded target subtrees — block and page embeds — followed recursively); `assignments_for()` (every `(vertex, assignment)` pair in a tree's render-visible document — the `transcluded_vertices()` set: tree vertices plus embed-transcluded content, so a merely-mentioned foreign page's own guffin metadata is excluded — whose assignment is for a given `Attribute`); `standalone_link_target_of_text()` (the vertex a text's *standalone* vertex link points at — the link as the text's entire content per `vertex_link.parse_standalone_vertex_link` — else `None`; container-agnostic, so it serves body text and table cells alike) and its vertex-level wrapper `standalone_link_target()` (a text-bearing vertex's standalone link target, else `None`); `visible_asset_vertices()` (every `AssetVertex` the render-visible document *displays*: assets among `transcluded_vertices()`, plus assets a render-visible vertex references standalone, plus assets a render-visible table cell references standalone; a merely-mentioned asset — linked inline amid text — renders as a remote hyperlink and is excluded); transformers `map_vertices()`, `drop_attribute_assignments()` (clears end-user assignments — the rendered attribute pills — while Guffin-system assignments stay in force, so `--suppress-attributes` never strips document metadata or render directives), `drop_code_sources()` (clears every code block's `code_source` provenance — tree and referenced vertices alike — so no source attribution renders; every renderer applies it unless `RenderOptions.emit_code_sources` is set), `drop_root_preamble()` (prunes the export root's loose preamble — children preceding its first heading child, whatever the root's vertex type), `enrich_image_original_sizes()`, `enrich_pdf_original_file_names()`
    - `vertex_view.py` — presentation overlay kept decoupled from content: `ChildrenLayout` StrEnum (bullet/document/numbered), `DEFAULT_CHILDREN_LAYOUT`, the two **classification** StrEnums — `Semantic` (the kind of thinking a vertex's content represents: `definition`/`leads-to`/`result`/`question`/`idea`/`corollary`/`contrast`/`evidence`/`conclusion`/`hypothesis`/`depends-on`/`warning`/`decision`/`reference`/`process`, naming the act of thought the content performs independently of whatever markup or extension vocabulary declared it) and `SourceChannel` (the medium the recorded material arrived through — `calendar-event`/`email`/`voice-call`/`chat-message`/`postal-mail`/`slack` — a capture channel, not an author or a location) — `VertexView` (per-vertex presentation state: `children_layout`, `semantic`, `source_channel`, **every field optional**, so an unset field asserts nothing about the vertex and each consumer's own resolution rules apply), `ViewMap` (sparse `{uid: VertexView}`)
    - `render_bundle.py` — `RenderBundle`: a `VertexTree` (content) paired with its `ViewMap` (presentation), held as separate fields so they travel together while staying decoupled, plus an optional `provenance: Provenance` (the software that produced the bundle's data) and an optional `revision: Revision` (the content snapshot it was produced from) — origin metadata a renderer stamps as one combined colophon line when `RenderOptions.emit_colophon` is set
    - `vertex_link.py` — custom `x-guffin` URL scheme for inter-vertex links; `VertexLinkKind`, `VertexLink`, `vertex_link_url()`, `parse_vertex_link()`, `is_vertex_link()`, `parse_standalone_vertex_link()` (parse a text that is a *standalone* Pandoc-Markdown-form vertex link `[<display>](<x-guffin-url>)` — the link as the text's entire content, the canonical text encoding a solo Roam reference transcribes to — recognized structurally with a DOTALL display so a multi-paragraph destination still parses)
    - `attribute.py` — normalized model of a Roam attribute's identity and values (the `<attribute>::` head and its value tokens): `Attribute` (an attribute's **graph-independent** identity — a `name` plus an `AttributeDomain` `domain`; equality/hashing are identity-based, so subclass instances compare equal to any `Attribute` with the same identity), `AttributeInstance` (a **graph-bound** occurrence of an `Attribute`, composing it with a `VertexLink` to its page in a specific Roam graph), the `AttributeValue` discriminated union (`LiteralValue` | `ReferenceValue`, with `AttributeValueKind` and `attribute_value_adapter`), the `AttributeDomain` StrEnum (`default`/`guffin`) naming the namespace an attribute belongs to (its `is_guffin` property marks the domain owned by the Guffin system, whose attributes carry system semantics and never appear directly in output content — the single source for pill-vs-system decisions), and the value helper `attribute_value_text()` (an `AttributeValue`'s text — its literal token or the referenced page name)
    - `attribute_assignment.py` — a whole Roam attribute assignment (`<attribute>:: <value>, …`) and the operations over it, built atop `attribute.py`: `AttributeAssignment` (an `AttributeInstance` paired with its ordered values), the single-value readers `sole_value()`/`sole_value_text()`/`verified_sole_value_text()` (the last verifies the assignment is for a given `Attribute` before reading), the identity predicate `is_assignment_for()` (does an assignment assign a given `Attribute` — name + domain) with its assertion form `verify_assignment_for()`, and `find_assignment_for()` (the first of a collection of assignments that is for a given `Attribute`). Depends only on `attribute.py`
    - `attribute_anchor.py` — the anchoring affordances an attribute vocabulary can declare, independent of any particular vocabulary's use of them: `TreePosition` (StrEnum `anywhere`/`root` — the positional axis) and `AttributeAnchor` (StrEnum `PAGE`/`HEADING`/`PDF`/`CODE_BLOCK`/`BLOCK`/`ANY`/`ROOT`, each member carrying three constraint axes a host vertex must satisfy: the `frozenset[VertexType]` it attaches to — the single source of truth for the AttributeAnchor↔VertexType correspondence; `BLOCK` covers every vertex type except a page, `ANY`/`ROOT` cover them all, derived from `VertexType` itself — its `TreePosition`, and `through_standalone_links` — whether the type constraint may alternatively be satisfied through a standalone vertex link, the host tagging the vertex its link references at that reference site (only `PDF` declares it); `AttributeAnchor.ROOT` is type-independent but accepts only the tree's root vertex, the export target itself). Depends only on `vertex.py`
    - `element_number.py` — internal element numbering, the author-maintained logical ordering of a document's elements: a bracketed dot-separated marker leading a heading's text (`[0.1]`, `[1.2.3]` — first text ignoring whitespace), encoding the element's relative, logical, hierarchical position independently of its placement in the source hierarchy; the fixed convention classifies the leading segment as the element's `Matter` division (`MATTER_BY_LEADING_SEGMENT`: 0 front, 1 body, 2 back), so a well-formed number has ≥ 2 segments (a bare `[1]` is malformed). `ElementNumber` (immutable, totally ordered by numeric tuple comparison; `matter` property, `is_prefix_of()`), `parse_element_number()` (a text's leading marker, else `None`), `stripped_element_number()` (a text without its well-formed leading marker; unchanged when it leads with none), the shape predicates `leads_with_element_number_shape()` / `leads_with_dotted_element_number_shape()` (an *attempted* marker — the dotted variant requires ≥ 1 dot, exempting bare `[1]` footnote/citation labels in prose) and their patterns (`ELEMENT_NUMBER_PATTERN`/`_RE`, `ELEMENT_NUMBER_SHAPE_PATTERN`/`_RE`, `ELEMENT_NUMBER_DOTTED_SHAPE_PATTERN`/`_RE`; page-ref `[[…]]` and Markdown-link `[…](` leads never match). Sits just above the taxonomy in the `model/` conceptual stack: depends only on `chicago_structure.py`
    - `code_source_diagnosis.py` — the pure judgment of a code block against its source reference, retrieval-free: `CodeSourceDiagnosis` (StrEnum `fetch-failure`/`drift`/`local-modification`), `CodeSourceFinding` (one block's failure: uid, url, diagnosis, detail), `code_matches_source()` (the single comparison policy — trailing newlines ignored, every other byte counts), and `diagnosed_finding()` (the three-way verdict over supplied evidence: matches the tip → verified; mismatched with an unmoved ref → local modification; else the snapshot content disambiguates drift from local modification, and is required exactly then). Sits near the **top of the `model/` conceptual stack**: may depend on `vertex.py` and `code_source.py`; neither may depend on it
    - `code_source.py` — the provenance of a code block's content: `CodeSource` (frozen; the GitHub blob `url` naming the source file at its ref — the human-usable click target, always parseable via `common/github_file_ref.parse_blob_github_url`; the raw fetch URL is derived from the parsed ref, never stored — the full 40-hex `commit_sha` actually fetched, immutable even when the URL's ref is a moving branch, and the `fetched_date` calendar day (a `datetime.date`, accepting the ISO string at validation); `file_ref()` yields the decomposed `GitHubFileRef`). ## Test Fixtures

Nine live Roam pages serve as the primary test sources: `[[Test Article]] 0`
through `[[Test Article]] 7`, plus `[[Test Article]] 8 has a **bold** word`.  Each
article exercises a distinct feature set — see `tests/fixtures/README.md` for the
per-article feature lists, which `tests/regen_fixtures.py` keeps in sync from a
callout on each live page.  A source page's title is normally exactly
`[[Test Article]] N`; article 8 relaxes this to a *prefix* because its feature —
`**bold**` emphasis on one portion of the page name — is a property of the title
itself.  For
each source, `tests/regen_fixtures.py` generates six fixture files that capture
different stages and views of the data pipeline.

### No-refs fixture set (`include_refs=False`) — a linear pipeline

Three fixtures representing successive stages of the export pipeline applied to
the anchor subtree alone, with no referenced pages included:

| Fixture | What it captures |
|---|---|
| `<prefix>_nodes.yaml` | The Roam nodes (page + blocks) as parsed `RoamNode` model objects |
| `<prefix>_vertices.yaml` | The same subtree transcribed into the export model (`VertexTree`) |
| `<prefix>_expected.md` | The fully rendered GFM output |

### With-refs fixture set (`include_refs=True`) — three views of the same fetch

Three fixtures derived from a single API call that pulls the anchor subtree
together with every page and block it references.  Rather than a pipeline, they
are three different lenses on the same underlying data:

| Fixture | What it captures |
|---|---|
| `<prefix>_raw_result.yaml` | The raw Datalog wire response before any `RoamNode` parsing |
| `<prefix>_anchor_tree.yaml` | The `NodeTree` of the anchor subtree itself (within the broader refs fetch) |
| `<prefix>_nodes_by_uid.yaml` | All fetched nodes — anchor subtree plus every referenced page/block — keyed by UID |

python tests/regen_fixtures.py "[[Test Article]] 3" --prefix test_article_3
python tests/regen_fixtures.py "[[Test Article]] 4" --prefix test_article_4
python tests/regen_fixtures.py "[[Test Article]] 5" --prefix test_article_5
python tests/regen_fixtures.py "[[Test Article]] 6" --prefix test_article_6
python tests/regen_fixtures.py "[[Test Article]] 7" --prefix test_article_7

## Git
- **Never commit or push without explicit instructions**: do not run `git commit` or `git push` unless the user explicitly asks. This applies even after completing a task — finish the work, then wait for the user to request a commit/push.

## Conventions
- Src layout: package lives under `src/guffin/`
- Line length: 120 chars (Black + Ruff)
- Docstrings: PEP 257 format (pydocstringformatter), Google style convention (Ruff)
- **Dependent-agnostic documentation**: a module, class, or function must document what it offers on its own terms — never how its dependents (importers/callers) consume it. Don't name downstream modules or describe their usage in upstream docstrings or comments (e.g. avoid "X and Y delegate their logic here" or "shared by Z"); describe behaviour through the API's own parameters and contract, so the documentation reads identically regardless of who depends on it.
- **`Public symbols:` docstring is a by-kind index**: the module-docstring `Public symbols:` block is a *categorized index* of the module's public API, grouped by kind (pattern constants → type aliases → enums → models/classes → functions), with related symbols kept contiguous within a group. It is **independent of definition order** — the body's order follows define-before-use and feature cohesion (e.g. a discriminated-union alias must be defined after its members, a Typer `app` before the `main` it decorates), so the index and the body deliberately need not match. Keep the index grouping coherent; do not reorder code to track it.
- **Tests**: pytest, files named `test_*.py`. The `tests/` tree mirrors `src/guffin/`:
  each test module lives in the subpackage of the module it covers
  (`tests/<package>/test_<module>.py`, e.g. `tests/roam/test_markdown.py` for
  `guffin/roam/markdown.py`, `tests/common/test_markdown.py` for `guffin/common/markdown.py`).
  pytest runs in `importlib` import mode (`addopts = "--import-mode=importlib"`), so test
  files need no `__init__.py` and basenames may repeat across packages. `tests/conftest.py`
  and `tests/regen_fixtures.py` stay at the `tests/` root; shared non-fixture helpers are
  imported via `from conftest import ...` (`tests/` is on `pythonpath`).
- **Strong typing**: all Python code must use type annotations throughout; no `Any` types. Enforced on two levels: pyright in strict mode (semantic — every expression must resolve to a known type) and ruff's `ANN` ruleset (syntactic — parameter and return annotations must be written explicitly, not inferred). Local-variable annotations (see **Immutable bindings**) remain convention — no tool enforces them
- **Regular expressions**: use the third-party `regex` package **exclusively** — never the stdlib `re` module. Import as `import regex` and use `regex.compile`, `regex.Pattern[str]`, `regex.Match[str]`, `regex.DOTALL`, etc. `regex` is a drop-in superset of `re` (it defaults to `re`-compatible behaviour) and additionally supports recursive patterns (e.g. `(?R)` for matching balanced, nestable Roam page references). `types-regex` (a dev dependency) provides the stubs required by pyright strict mode.
- **Bash tool calls**: never chain multiple commands with `&&` in a single Bash tool call; use separate Bash tool calls instead. Never use heredoc embeds (`$(cat <<'EOF'...EOF)`) or ANSI-C quoting (`$'...'`) in Bash tool calls; both embed literal newlines in the command string, which prevents permission-pattern matching. For `git commit` messages that need multiple paragraphs, use repeated `-m` flags instead: `git commit -m "subject" -m "body" -m "Co-Authored-By: ..."` — each `-m` becomes a blank-line-separated paragraph.
- **Logging format**: all `logger.*()` calls must use `%`-style format strings (e.g., `logger.info("x=%s", x)`) — never f-strings (e.g., `logger.info(f"x={x}")`); this enables lazy interpolation and better log aggregation in monitoring tools.
- **`@validate_call`**: decorate every public function and method (non-`_`-prefixed, non-dunder) with `@validate_call`. Exceptions: `@property` methods (technically incompatible), Pydantic model lifecycle methods (`model_*`, field validators, `__init__`), CLI entry-point functions wired by argparse, methods overriding non-Pydantic framework interfaces, generic functions whose type variables cannot be resolved at runtime, and classmethods/staticmethods whose return-type annotation references the class being defined (pydantic eagerly evaluates type hints at decoration time, before the class is added to module globals, causing a `NameError`). For `@staticmethod` and `@classmethod` methods that qualify, `@validate_call` is placed innermost — just above `def`, below the `@staticmethod`/`@classmethod` line. When a function has panflute (or other arbitrary-type) parameters, use `@validate_call(config=ConfigDict(arbitrary_types_allowed=True))` instead of plain `@validate_call`.
- **Immutable bindings**: all local variables and module-level constants must be annotated `Final[T]` by default (e.g., `x: Final[int] = 1`, `MY_CONST: Final[str] = "value"`); only omit `Final` when the binding genuinely needs to be reassigned. Inside Pydantic models, use `ClassVar[T]` for class-level constants (Pydantic excludes these from model fields).
- **Side-effect-free functions**: side-effect-free functions are very highly valued — a function computes and returns a value; it must never mutate its arguments. State updates (dict inserts, accumulator writes) belong at the call site that owns the state. Declare read-only intent in signatures with abstract types (`Mapping` not `dict`, `Sequence` not `list`) for parameters that are only read, and name value-producing helpers as values (`_resolved_file_name`), not actions (`_claim_file_name`). Functions whose *purpose* is an effect (I/O, caching, rendering) are of course legitimate — keep effects there, at the edges, and out of computation helpers.
- **Parameter names**: function and method parameter names must be at least 3 characters long; single- and two-character names (e.g. `s`, `fn`, `cb`) are not allowed.

## Architecture
- **CLI isolation**: only modules in the `cli/` sub-package may import or use the Typer package (the entry points `export_roam_tree.py` / `dump_roam_tree.py` and CLI-only support modules such as `cli/params.py`). All modules outside `cli/` must be front-end agnostic so they can be used outside a CLI context without pulling in CLI dependencies. Within `cli/`, keep Typer out of modules that have a non-CLI reason to stay framework-free (e.g. `cli/common.py`, whose helpers are unit-tested directly).
- **Exit-point isolation**: all explicit process-exit calls (`typer.Exit`, `sys.exit`, etc.) must live exclusively in the CLI modules. Library code propagates exceptions; CLIs decide whether and how to exit. This keeps control-flow transparent and makes library code testable without mocking exit behaviour.
- **Post-processing isolation**: any *post-processing* for an output format — a transform of that format's rendered **output**, applied *after* the Pandoc/Typst conversion — must live in `render/<format>_post_processing.py`, never inline in the `<format>_rendering.py` renderer; a format with no post-processing omits the module entirely (no empty placeholder). Each post-processing module is a private stage of one format's pipeline: it is imported only by its own `<format>_rendering.py`, never by another renderer or a shared render utility. Currently `render/epub_post_processing.py` (packaged-`.epub` rewrites) and `render/md_post_processing.py` (GFM text cleanup) exist; the PDF path has no post-processing and no module. *Pre*-conversion transforms — model-tree prunes and Panflute `Doc` rewrites (e.g. `pdf_rendering._apply_pdf_embeds`) — are **not** post-processing and stay in the renderer/model layers. Enforced by `tests/test_architecture.py::TestPostProcessingSegregation` (module↔renderer correspondence + single-consumer imports); the no-inline-post-processing half is a semantic rule kept by review.
- **Semantic-vocabulary isolation**: `model/publishing_semantics.py` (`PublishingSemantics`/`PublishingAttribute`) and the modules it composes — the `model/attribute_anchor.py` anchoring affordances (`AttributeAnchor`/`TreePosition`) and the `model/chicago_structure.py` taxonomy its tag values come from (`Matter`/`StructuralElement`) — form a **format-independent vocabulary aligned with publishing-industry conventions**; none of them may ever depend on, or be named after, any output format. The affordance/taxonomy modules are deliberately separate from the vocabulary because what the model *can express* is independent of how the guffin vocabulary *chooses to use it*. Within `model/`, `chicago_structure.py` is a pure taxonomy at the **bottom of the conceptual stack** (no `guffin` dependencies), `attribute_anchor.py` sits just above the primitives (depends only on `vertex.py`), and `element_number.py` sits just above the taxonomy (depends only on `chicago_structure.py`), while `publishing_semantics.py` sits **near the top**: it may depend on the structural primitives (`attribute.py`, `attribute_assignment.py`, `vertex.py`, `vertex_tree.py`), `attribute_anchor.py`, `chicago_structure.py`, and `element_number.py`, but none of those may depend on `publishing_semantics.py` — vocabulary-aware helpers (e.g. `find_publishing_attribute()`, `has_parts()`) therefore live in `publishing_semantics.py`, not on the primitives. `model/publishing_validation.py` (the vocabulary's validation pass, culminating in `validate_semantics()`) sits at the **very top**, directly above `publishing_semantics.py`: it judges trees against the vocabulary — definition and judgment are deliberately separate modules — and nothing in `model/` may depend on it. Member names follow publishing labels, some deliberately diverging from format-specific terms (e.g. `table-of-contents`/`list-of-illustrations`, not EPUB SSV's `toc`/`loi`). Each per-format mapping (`StructuralElement → EpubType` in `render/epub_semantics.py`, and future `→ PDF`, `→ GFM`) lives in `render/` and is keyed on the enum member — never a name-equality lookup against a format's own vocabulary. See `docs/publishing-semantics.md`.

### Sub-package dependency rules

| Package | May depend on | May NOT depend on |
|---|---|---|

| `roam/` | `common/` | `guffin` root modules, `model/`, `transcribe/`, `render/`, `cli/` |
| `model/` | `common/` | `guffin` root modules, `roam/`, `transcribe/`, `render/`, `cli/` |
| `guffin` (root modules) | `roam/`, `common/`, `model/` | `transcribe/`, `render/`, `cli/` |
| `transcribe/` | `common/`, `roam/`, `model/`, `guffin` root modules | `render/`, `cli/` |
| `render/` | `common/`, `roam/`, `model/`, `guffin` root modules | `transcribe/`, `cli/` |
| `cli/` | `common/`, `roam/`, `model/`, `guffin` root modules, `transcribe/`, `render/`, `server/` (the `serve.py` launcher only) | — |

No *library* package may take a dependency on the front-end packages `cli/` or `server/` (enforced by `tests/test_architecture.py::TestFrontEndIsolation`).

## Modern Python Requirements (Python 3.14)
All code written or modified by Claude MUST follow these conventions — no exceptions:

- **Built-in generics**: always `list[x]`, `tuple[x, y]`, `dict[k, v]`, `set[x]` — never `List`, `Tuple`, `Dict`, `Set` from `typing`
- **Union syntax**: always `X | Y` and `X | None` — never `Union[X, Y]` or `Optional[X]`
- **Type aliases**: always `type Foo = ...` (PEP 695) — never `Foo: TypeAlias = ...` or bare `Foo = ...`. Exception: a shared **Typer parameter alias** (`Name = Annotated[T, typer.Option(...)]` / `typer.Argument(...)` reused across CLI commands, e.g. in `cli/params.py`) must use a plain assignment, because Typer reads the embedded `Option`/`Argument` metadata off the annotation object and cannot resolve it through a PEP 695 `TypeAliasType` (it raises `RuntimeError: Type not yet supported`).
- **No `from __future__ import annotations`**: not needed in Python 3.14 (PEP 649 deferred evaluation is the default)
- **No string-quoted forward references**: never `"ClassName"` in annotations; if a forward reference is needed, reorder definitions so the referenced name is declared first
- **No `cast()`**: never use `typing.cast()`; fix the type properly instead
- **No `Any`**: never use `typing.Any`; use a precise type or a type variable
- **Enum mixin subclasses**: always use the dedicated single-inheritance mixin — never mix a built-in type with `Enum`/`Flag` directly (Ruff `UP042`):
  - `class Foo(str, Enum)` → `class Foo(enum.StrEnum)`
  - `class Foo(int, Enum)` → `class Foo(enum.IntEnum)`
  - `class Foo(int, Flag)` → `class Foo(enum.IntFlag)`

## Environment Variables
- `GUFFIN_ROAM_LOCAL_API_PORT` — port for Roam Local API (all CLI tools)
- `GUFFIN_ROAM_GRAPH_NAME` — Roam graph name (all CLI tools)
- `GUFFIN_ROAM_API_TOKEN` — bearer token for auth (all CLI tools)
- `GUFFIN_EXPORT_DIR` — output directory for `export-roam-tree`
- `GUFFIN_CACHE_DIR` — directory for caching downloaded Cloud Firestore assets (both commands; backs `--cache-dir`/`-c`). In `dump-roam-tree` only the render-bundle view fetches assets — to read each image's native pixel size and each PDF's original filename — so without it every dump re-downloads them
- `GUFFIN_PDF_TEMPLATE_DIR` — directory containing a `user_cfg.typ` override for PDF styling (`export-roam-tree --format pdf`)
- `GUFFIN_DUMP_PANDOC_AST` — set to any non-empty value to dump the Pandoc JSON AST to `<output-dir>/<target>.pandoc.json` before the Pandoc conversion step (`export-roam-tree`, all formats)
- `GUFFIN_PANDOC_SERVER` — set truthy (`1`/`true`/`yes`/`on`) to route the Markdown→Pandoc-JSON parse through a persistent per-process `pandoc-server` (`render/pandoc_server.py`) instead of spawning a fresh Pandoc process (~87ms startup) per parse; when unset/falsy or the server is unavailable, `pandoc_ast` falls back to the Pandoc CLI, so output is unchanged. Off by default in production; `tests/conftest.py` sets it (via `setdefault`, so `GUFFIN_PANDOC_SERVER=0` forces the CLI path) to speed up the test suite's many small renders
- `GUFFIN_INCLUDE_PREAMBLE` — backs the `--preamble/--no-preamble` flag (`export-roam-tree`, pdf/epub only); set truthy/falsy (e.g. `true`/`0`) to keep/drop the export root's loose preamble; unset, the `--type` profile decides (book drops, others keep)
- `GUFFIN_NUMBER_SECTIONS` — backs the `--numbering/--no-numbering` flag (`export-roam-tree`, pdf/epub only); set truthy/falsy to turn all heading numbering on/off; unset, the `--type` profile decides (book numbers, others don't)
- `GUFFIN_ELEMENT_NUMBERS` — backs the `--element-numbers/--no-element-numbers` flag (`export-roam-tree`, all formats); set truthy to keep internal element numbers (heading `[1.2.3]` leads) in the exported document; default (unset/falsy) strips them
- `GUFFIN_CODE_SOURCES` — backs the `--code-sources/--no-code-sources` flag (`export-roam-tree`, all formats); set truthy to render each sourced code block's GitHub attribution line below the listing; default (unset/falsy) omits them
- `GUFFIN_VERIFY_CODE_SOURCES` — backs the `--verify-code-sources/--no-verify-code-sources` flag (`export-roam-tree` and `dump-roam-tree`; **default on**); set falsy (e.g. `0`) to skip the GitHub verification of `code-source::`-tagged code blocks — the offline path (findings abort an export; they are advisory warnings in a dump)
- `GUFFIN_GITHUB_TOKEN` — optional GitHub token for ref resolution (`common/github_fetch.py`, used by the code-source verification); sent as a bearer credential on `api.github.com` requests only (never to `raw.githubusercontent.com`), raising the rate limit from 60/h per IP to 5,000/h per token
- `GUFFIN_DAILY_NOTE_FORMAT` — backs the `--daily-note-format` flag (`export-roam-tree`, all formats); `roam-long` (default; a daily-note-page reference keeps the page's own verbose title, so output is unchanged), `iso` (renders those references as ISO 8601 dates), or `abbrev-month-day` (abbreviated month + day, no year, e.g. `Jan 1`)
- `GUFFIN_EMIT_COLOPHON` — backs the `--colophon/--no-colophon` flag (default on); set falsy (e.g. `0`) to omit the colophon (software provenance — source commit + export time — and content revision — snapshot hash + edit/fetch times + authored `revision::` name) from output (`export-roam-tree`, all formats). Placement differs by format: PDF renders it at the foot of the title page when one is emitted (Bergfink `titlepage-provenance`), else on a line below the running page footer (`footer-provenance`); EPUB mirrors the PDF rules — stamped at the foot of the generated title page when one is emitted (`epub_post_processing.stamp_titlepage_provenance`), else an end-of-document block; Markdown carries it as an end-of-document block. The test suite forces it off via an autouse conftest fixture so byte-for-byte fixtures stay stable
- `GUFFIN_DUMP_TYPST` — set to any non-empty value to dump the intermediate Typst sources `<output-dir>/<target>.body.typ` (bare body) and `<output-dir>/<target>.full.typ` (with template applied) for debugging (`export-roam-tree --format pdf`); no effect on the produced PDF
- `GUFFIN_PDF_CREATION_TIMESTAMP` — UNIX timestamp passed to Typst via Pandoc `--pdf-engine-opt=--creation-timestamp` to pin the PDF creation date for byte-reproducible output (`export-roam-tree --format pdf`); used by the live PDF fixture test
- `GUFFIN_SERVER_HOST` — bind address for `guffin-server` (backs `--host`; default `127.0.0.1` — binding a network address exposes the server, and the Roam bearer tokens riding in request bodies, to that network)
- `GUFFIN_SERVER_PORT` — TCP port for `guffin-server` (backs `--port`/`-p`; default `8077`)
- `GUFFIN_LIVE_TESTS` — set to any non-empty value to enable live tests (e.g. `GUFFIN_LIVE_TESTS=1`); requires Roam Desktop running locally
