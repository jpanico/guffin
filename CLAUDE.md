# CLAUDE.md

## Project Overview
Python 3.14 toolkit for exporting Roam Research pages to self-contained
documents.  Supports three output formats:

- **Markdown** — renders to GFM and optionally bundles Cloud
  Firestore-hosted images and PDFs into a self-contained `.mdbundle` directory.
- **PDF** — builds a Pandoc object model directly from the `VertexTree`
  via Panflute, fetches and embeds Cloud Firestore images and PDF assets
  (attached originals; optionally inline-rendered pages), and produces a
  PDF via Pandoc + Typst (the bundled Bergfink template).
- **EPUB** — builds the same Pandoc object model and produces an EPUB 3
  e-book via Pandoc, with images embedded into the package.

Orthogonal to the format, a **project type** (`default`/`book`/`manuscript`,
CLI `--type`) says what *kind* of work is being produced; its structural
policy drives title page, heading numbering, chapter/part pagination, and
preamble handling in the paginated formats.  Document structure and
bibliographic metadata are declared in the Roam content itself through the
format-independent `guffin`-domain attribute vocabulary (`guffin-meta::`
metadata, `element-type::`/`matter::` heading tags), which each renderer
maps to its format's own conventions.

## Key Commands
```bash
dump-roam-tree <page_title_or_node_uid> -p <port> -g <graph> -t <token> [-v/-V] [-n/-N] [-r/-R] [--show-transient/--no-show-transient] [--node-props <props>]
export-roam-tree <page_title_or_node_uid> -p <port> -g <graph> -t <token> -o <output_dir> [--format markdown|pdf|epub] [--type default|book|manuscript] [--bundle|--no-bundle] [--cache-dir <dir>] [--template-dir <dir>] [--suppress-attributes] [--colophon|--no-colophon] [--preamble|--no-preamble] [--numbering|--no-numbering] [--daily-note-format roam-long|iso|abbrev-month-day]
# output filename stem embeds the project type: <target>.<type>.<ext> (e.g. Foo.default.epub, Foo.book.pdf)
# --format markdown (default): writes <target>.<type>.mdbundle/ (--bundle) or <target>.<type>.md (--no-bundle)
# --format pdf: writes <target>.<type>.pdf via Pandoc + Typst; requires typst on PATH
# --format epub: writes <target>.<type>.epub (EPUB 3) via Pandoc; requires pandoc on PATH (no typst)
# --type (-T): project profile (default/book/manuscript); appended to the output filename stem; plumbed to all renderers (all five structural directives applied in the paginated formats — top_level_division, number_sections, emit_title_page, emit_toc, drop_preamble — plus bibliographic metadata from a root page's guffin-meta:: attributes; markdown expresses emit_title_page as a YAML front-matter block carrying the document metadata, the title both there and as the leading H1)
# --preamble/--no-preamble (pdf/epub only): keep or drop the export root's loose preamble (children before its first heading); unset, the --type profile decides (book drops, others keep)
# --numbering/--no-numbering (pdf/epub only): turn all heading numbering on or off; unset, the --type profile decides (book numbers, others don't)
# --daily-note-format (all formats): how a reference/link to a Roam daily-note page renders its date — roam-long (default; the page's own verbose title, e.g. January 1st, 2026, so output is unchanged), iso (ISO 8601, e.g. 2026-01-01), or abbrev-month-day (abbreviated month + day, no year, e.g. Jan 1)
# a book auto-detects parts from its content (cli/common.resolve_profile): any level-1 heading tagged element-type:: part switches the book to the PART division — chapters live at level 2, the EPUB splits files at level 2, and the PDF opens both parts and chapters on a new page
# a {{[[pdf]]: <url>}} embed is content-tag controlled in the PDF format: untagged it renders as the PDF's original filename in plain text (no link), tagged pdf-render:: inline (a guffin-meta:: child of the embed block) all of its pages render in the document flow (one full-width image per page, requires typst >= 0.14); the PDF file itself is never embedded in the output (matching the epub format)
# --template-dir: directory containing user_cfg.typ overrides for PDF styling (pdf only)

# Run the full check pipeline (format + lint + type check + tests) in one shot.
# The test step is `test-heavy`, so live tests run too — requires Roam Desktop running locally:
hatch run check

# Individual steps (run in this order):
pydocstringformatter --write src/ # reflow docstring content (PEP 257)
black .                           # format code
ruff check --fix src/ tests/      # lint + fix docstring style (Google convention)
pyright                           # type check (strict)
pytest                            # run tests (excludes live tests)

# Test tiers (defined as hatch scripts in pyproject.toml), lightest to heaviest:
hatch run test-light   # skips pandoc-subprocess-bound integration tests (marked `pandoc`); the fast inner loop (~2.5s)
hatch run test-medium  # the full offline suite
hatch run test-heavy   # everything, live tests included; requires Roam Desktop running locally; the tier `check` runs

# Live tests only, directly (requires Roam Desktop running locally):
GUFFIN_LIVE_TESTS=1 pytest -m live -v
```

## Project Structure
- `src/guffin/` — main package
  - **`cli/` sub-package** (`src/guffin/cli/`) — CLI entry points and supporting infrastructure
    - `dump_roam_tree.py` — dumps a Roam page or node subtree as a Rich tree to the terminal; supports `--render-bundle`/`--node-tree`/`--raw-results` flags, plus `--show-transient` to include the transient session/UI attribute columns (hidden by default) in the raw-results table (`dump-roam-tree`). The `--render-bundle` (`-b`) view renders both parts of the `RenderBundle`: an outer panel over a `Vertex Tree` sub-panel (the content `VertexTree`) followed by a `View Map` sub-panel (the presentation `ViewMap`, as a tree of only the vertices carrying a view entry plus the ancestors linking them to the root, each panel titled like its vertex panel and bodying its `VertexView`)
    - `export_roam_tree.py` — exports a Roam page or node subtree; `--format markdown` (default) writes a `.mdbundle` or plain `.md`; `--format pdf` writes a PDF via Panflute + Pandoc + Typst; `--format epub` writes an EPUB 3 e-book via Panflute + Pandoc; target is a page title or node UID (`export-roam-tree`)
    - `logging_config.py` — colorized logging (`configure_logging()`); reads `LOG_LEVEL` env var
    - `common.py` — tree-loading pipeline for CLI commands; `fetch_roam_trees` resolves a target, fetches nodes, and returns a `(NodeFetchResult, VertexTree | None)` pair, running `validate_semantics` on the transcribed content (violations warn by default, or raise `SemanticsValidationError` when called with `strict_semantics=True` — export does, dump doesn't); `resolve_profile` builds the `ProjectProfile` for a project type, refined by the content (a book with part-tagged level-1 headings becomes a parts book); every vertex-tree fetch also captures the content `Revision` (snapshot hash from the raw wire response via `roam/revision.gather_revision`, revision name from the root's authored `revision::` attribute) onto the returned bundle
  - **`model/` sub-package** (`src/guffin/model/`) — core normalized-graph model: UID primitives, vertex types, tree, presentation overlay, render bundle, and inter-vertex links
    - `primitives.py` — foundational UID primitives for the model: `Uid`, `SYNTHETIC_UID_PATTERN`/`DAILY_NOTE_UID_PATTERN`/`UID_PATTERN`/`UID_RE`, `ANCHORED_UID_PATTERN`/`ANCHORED_UID_RE`, `is_daily_note_uid()` (dependency root)
    - `vertex.py` — `VertexType` StrEnum classifying each vertex by the shape of its source `RoamNode` (`PAGE`/`TEXT`/`HEADING`/`IMAGE`/`PDF`/`CALLOUT`/`CODE_BLOCK`/`BLOCK_QUOTE`/`TABLE`/`BLOCK_EMBED`/`PAGE_EMBED`); the `Vertex` union and all eleven concrete vertex types (`PageVertex`, `HeadingVertex`, `TextVertex`, `ImageVertex`, `PdfVertex`, `CalloutVertex`, `CodeBlockVertex`, `BlockQuoteVertex`, `TableVertex`, `BlockEmbedVertex`, `PageEmbedVertex`); the `PageVertex.daily_note_date` field (the `datetime.date` a page represents when its `uid` is an `MM-DD-YYYY` daily-note date, else `None`; set once at transcription, letting a renderer format daily-note references by date rather than the Roam-authored title); the shared `_BaseVertex.attribute_assignments` field holding folded Roam attribute assignments (`<attribute>:: <value>, …`); `find_attribute_assignment()` looks up a vertex's folded assignment for an `Attribute` (delegating to `attribute.find_assignment_for()`); the `AssetVertex` union of the asset-bearing vertex types (`ImageVertex | PdfVertex` — content is a Cloud Firestore-hosted file, not inline text; the union is the single source of truth for asset-bearing-ness) with its narrowing predicate `is_asset_vertex()` (checks against a runtime tuple derived from the union itself); the `EmbedVertex` union of the transcluding vertex types (`BlockEmbedVertex | PageEmbedVertex` — content is the EMBED-linked target reproduced at the embed site; same single-source-of-truth pattern) with its narrowing predicate `is_embed_vertex()`; `VertexChildren`, `VertexRefs`, `vertex_adapter`
    - `vertex_tree.py` — `VertexTree`, `VertexTreeDFSIterator`, `root_vertex()`; `transcluded_vertices()` (the render-visible vertices: tree vertices plus embed-transcluded target subtrees — block and page embeds — followed recursively); `assignments_for()` (every `(vertex, assignment)` pair in a tree — refs included — whose assignment is for a given `Attribute`); transformers `map_vertices()`, `drop_attribute_assignments()` (clears end-user assignments — the rendered attribute pills — while Guffin-system assignments stay in force, so `--suppress-attributes` never strips document metadata or render directives), `drop_root_preamble()` (prunes the export root's loose preamble — children preceding its first heading child, whatever the root's vertex type), `enrich_image_original_sizes()`, `enrich_pdf_original_file_names()`
    - `vertex_view.py` — presentation overlay kept decoupled from content: `ChildrenLayout` StrEnum (bullet/document/numbered), `DEFAULT_CHILDREN_LAYOUT`, `VertexView`, `ViewMap` (sparse `{uid: VertexView}`)
    - `render_bundle.py` — `RenderBundle`: a `VertexTree` (content) paired with its `ViewMap` (presentation), held as separate fields so they travel together while staying decoupled, plus an optional `provenance: Provenance` (the software that produced the bundle's data) and an optional `revision: Revision` (the content snapshot it was produced from) — origin metadata a renderer stamps as one combined colophon line when `RenderOptions.emit_colophon` is set
    - `vertex_link.py` — custom `x-guffin` URL scheme for inter-vertex links; `VertexLinkKind`, `VertexLink`, `vertex_link_url()`, `parse_vertex_link()`, `is_vertex_link()`
    - `attribute.py` — normalized model of a Roam attribute's identity and values (the `<attribute>::` head and its value tokens): `Attribute` (an attribute's **graph-independent** identity — a `name` plus an `AttributeDomain` `domain`; equality/hashing are identity-based, so subclass instances compare equal to any `Attribute` with the same identity), `AttributeInstance` (a **graph-bound** occurrence of an `Attribute`, composing it with a `VertexLink` to its page in a specific Roam graph), the `AttributeValue` discriminated union (`LiteralValue` | `ReferenceValue`, with `AttributeValueKind` and `attribute_value_adapter`), the `AttributeDomain` StrEnum (`default`/`guffin`) naming the namespace an attribute belongs to (its `is_guffin` property marks the domain owned by the Guffin system, whose attributes carry system semantics and never appear directly in output content — the single source for pill-vs-system decisions), and the value helper `attribute_value_text()` (an `AttributeValue`'s text — its literal token or the referenced page name)
    - `attribute_assignment.py` — a whole Roam attribute assignment (`<attribute>:: <value>, …`) and the operations over it, built atop `attribute.py`: `AttributeAssignment` (an `AttributeInstance` paired with its ordered values), the single-value readers `sole_value()`/`sole_value_text()`/`verified_sole_value_text()` (the last verifies the assignment is for a given `Attribute` before reading), the identity predicate `is_assignment_for()` (does an assignment assign a given `Attribute` — name + domain) with its assertion form `verify_assignment_for()`, and `find_assignment_for()` (the first of a collection of assignments that is for a given `Attribute`). Depends only on `attribute.py`
    - `attribute_anchor.py` — the anchoring affordances an attribute vocabulary can declare, independent of any particular vocabulary's use of them: `TreePosition` (StrEnum `anywhere`/`root` — the positional axis) and `AttributeAnchor` (StrEnum `PAGE`/`HEADING`/`PDF`/`BLOCK`/`ANY`/`ROOT`, each member carrying two constraint axes a host vertex must satisfy: the `frozenset[VertexType]` it attaches to — the single source of truth for the AttributeAnchor↔VertexType correspondence; `BLOCK` covers every vertex type except a page, `ANY`/`ROOT` cover them all, derived from `VertexType` itself — and its `TreePosition`; `AttributeAnchor.ROOT` is type-independent but accepts only the tree's root vertex, the export target itself). Depends only on `vertex.py`
    - `chicago_structure.py` — a book's structural anatomy, aligned with the **Chicago Manual of Style (CMOS)**: `Matter` (StrEnum `front-matter`/`body-matter`/`back-matter` — a book's top-level division) and `StructuralElement` (StrEnum of a book's organizational parts `TITLE_PAGE`…`COLOPHON`, each carrying the `Matter` division it *conventionally* belongs to per CMOS, independent of any output format — the values an `element-type` tag takes; no `cover` member, since per CMOS only the book interior is matter-classified: the cover is exterior, supplied as metadata / a cover image). A pure taxonomy at the **bottom of the `model/` conceptual stack**: depends on nothing else in `guffin`; anything in `model/` may depend on it
    - `publishing_semantics.py` — Guffin's own attribute vocabulary (format-independent, publishing-standard): `PdfRender` (StrEnum `inline`/`link` — how an embedded PDF asset is placed in paginated output; `DEFAULT_PDF_RENDER` is `link`), `PublishingAttribute` (an `Attribute` subclass that pins `domain` to `AttributeDomain.GUFFIN` and adds a required `anchor.AttributeAnchor`), `PublishingSemantics` (an `enum.Enum` of `PublishingAttribute` — root-anchored document metadata `TITLE`/`SUBTITLE`/`AUTHORS`/`ILLUSTRATORS`/`DATE`/`PUBLISHER`/`RIGHTS`/`IDENTIFIER`/`LANGUAGE`/`DESCRIPTION`/`REVISION`/`COVER_IMAGE` (illustrators are supportive contributors, not co-creators — Pandoc `contributor` role `illustrator`, EPUB `dc:contributor` + MARC `ill`, an "Illustrations by …" credit below the authors on the PDF/EPUB title pages) (bibliographic facts about the work as a whole, legal only on the export root; the cover is metadata rather than a `StructuralElement` because per CMOS the cover is exterior to the matter-classified interior — its value is a Roam block reference `((<uid>))` to an image block), the heading-anchored `ELEMENT_TYPE` and `MATTER` tags, the pdf-anchored `PDF_RENDER` tag, plus the block-anchored `PUBLISH` tag (`publish:: false` omits the tagged vertex and its whole subtree from every rendered output; `DEFAULT_PUBLISH` is `True`); `_value_` typed as `PublishingAttribute`), and the functions `element_type_of()` / `matter_of()` / `pdf_render_of()` / `publish_of()` (read an `element-type` / `matter` / `pdf-render` / `publish` assignment's value as a `StructuralElement` / `Matter` / `PdfRender` / `bool`, rejecting non-members), `find_publishing_attribute()` (a vertex's assignment for a `PublishingSemantics` attribute), `cover_image_of()` (read a `cover-image` assignment's value as the referenced image block's `Uid`), the tolerant per-vertex readers `element_type_of_vertex()`/`matter_of_vertex()`/`pdf_render_of_vertex()`/`publish_of_vertex()` (absent or illegal tags resolve to `None` with a warning), `cover_image_vertex()` (resolve a tree's cover to the `ImageVertex` its root references, tolerantly) and `resolved_matter()` (a heading's resolved `Matter` division — a bare `matter::` tag overrides the element's conventional placement, logging any disagreement), `has_parts()` (whether any render-visible level-1 heading in a `VertexTree` — embed-transcluded headings included — is tagged `element-type:: part`), `has_element_type()` (whether any render-visible heading is tagged with a given `StructuralElement`), `drop_unpublished()` (the tree transformer every renderer applies first: prunes each `publish:: false` vertex with its whole subtree, embeds of pruned content vanishing with it to a fixpoint; an unpublished export root raises), and the vocabulary validation pass — the `common/validation` `Validator`s `all_attributes_anchored()` (every recognized guffin attribute must sit on one of its anchor's vertex types — the `PublishingAttribute.anchor` invariant), `all_element_type_values_legal()` / `all_matter_values_legal()` / `all_pdf_render_values_legal()` / `all_publish_values_legal()` (every `element-type` / `matter` / `pdf-render` / `publish` value must be a `StructuralElement` / `Matter` / `PdfRender` member / boolean literal), `all_date_values_legal()` (every `date` value must be a W3CDTF reduced-precision date — `YYYY`, `YYYY-MM`, or `YYYY-MM-DD`; the Bergfink PDF template renders the reduced forms verbatim rather than through `dateformat`), `all_cover_image_values_legal()` (every `cover-image` value must be a block reference resolving to an `ImageVertex` present in the tree), and `all_matter_tags_at_section_level()` (a `matter` tag sits at the book's section level — level 1, or level 2 in a parts book, since that is where chapter-shaped sections live), run via `validate_semantics()` (accumulates a `ValidationResult`; `cli/common.fetch_roam_trees` runs it on every fetch — advisory warnings for `dump-roam-tree`, but `export-roam-tree` fetches with `strict_semantics=True`, so violations raise `SemanticsValidationError` and abort the export with exit 1). Sits at the **top of the `model/` conceptual stack**: it may depend on the structural primitives (`attribute.py`, `attribute_assignment.py`, `vertex.py`, `vertex_tree.py`), the `attribute_anchor.py` affordances, and the `chicago_structure.py` taxonomy, and none of them may depend on it
  - **`transcribe/` sub-package** (`src/guffin/transcribe/`) — the source→model bridge: source-to-model transcription and text normalization (shared by every use — export, dump, future interchange)
    - `roam_md_to_pandoc_md.py` — converts Roam-flavored Markdown strings to Pandoc Markdown; `to_pandoc_md()` is the main entry point
    - `roam_tree_to_guffin.py` — transcribes a `NodeTree` into the guffin render model: `transcribe()` derives the `VertexTree` content (applying `to_pandoc_md()` to all text fields), `build_view_map()` derives the presentation `ViewMap`, and `to_render_bundle()` bundles both into a `RenderBundle`
  - **`render/` sub-package** (`src/guffin/render/`) — output rendering: turns the normalized model into consumable output (document export and terminal display) plus the configuration and bundled resources that drive it
    - `date_format.py` — how a `datetime.date` renders as text: `DateFormat` (StrEnum `roam-long`/`iso`/`abbrev-month-day`; `ROAM_LONG` is Roam's verbose long-form date — English month + ordinal day + year, e.g. `January 1st, 2026`, the style Roam uses for daily-note page titles; `ABBREV_MONTH_DAY` is an abbreviated month + day of month with no year, e.g. `Jan 1`) and `format_date()` (render a `datetime.date` per a `DateFormat`). A general date-formatting utility with no dependency on the vertex model; the daily-note application lives in its consumers (`pandoc_rendering.make_resolver` reformats daily-note-page references, carried into the render entry points on `RenderOptions.daily_note_format`)
    - `render_options.py` — immutable export settings carried from a front end to a rendering entry point: `OutputFormat` (markdown/pdf/epub enum discriminator), `RenderOptions` (format-independent base: `output_dir`, `cache_dir`, `suppress_attributes`, `dump_pandoc_ast`, `emit_colophon` — the boolean opt-in to stamp the bundle's provenance as a colophon; the provenance *data* lives on `RenderBundle`, not here; and `daily_note_format` — the `DateFormat` for daily-note-page references, defaulting to `ROAM_LONG`), and the per-format subclasses `MarkdownRenderOptions` (`should_bundle`), `PdfRenderOptions` (`template_dir`, `include_preamble`, `number_sections`), and `EpubRenderOptions` (`include_preamble`, `number_sections`) — `include_preamble` and `number_sections` are tri-state overrides of the profile's `drop_preamble` / `number_sections` directives (`None` defers to the policy; they back the CLI `--preamble/--no-preamble` and `--numbering/--no-numbering`); the `RenderOptions.for_format(output_format, …)` static factory builds the right subclass from the full knob set (the single assembly point the CLI calls, so it threads one options object rather than a long parameter list)
    - `project.py` — the *kind* of work being rendered, modeled on Quarto's `project: type:` (concept only — no Quarto artifacts): `ProjectType` (default/book/manuscript discriminator; each member also carries a one-line `description`, the single source for the CLI `--type` help), `TopLevelDivision` (section/chapter/part), the `ProjectProfile` base + per-type subclasses `DefaultProfile`/`BookProfile`/`ManuscriptProfile`, `StructuralPolicy` (format-independent structural directives a profile resolves to), and `profile_for()` (maps a `ProjectType` to its default-valued profile). Orthogonal to `OutputFormat`; a `profile: ProjectProfile` is plumbed into every render entry point (via the CLI `--type` flag). All five structural directives are applied in both paginated formats — `top_level_division` (EPUB `--split-level`; PDF book mode: chapter page breaks + level-1 numbering), `number_sections`, `emit_title_page` (PDF Bergfink `titlepage`; EPUB `--epub-title-page`), `emit_toc` (book-only default: the work presents a navigable ToC — PDF renders a linked Typst outline at the start of the flow (Bergfink `toc` variable), suppressed by an authored `element-type:: table-of-contents` section via `has_element_type()`; EPUB deliberately maps it to nothing extra, since the always-generated nav document already feeds the reading system's own ToC affordance and `--toc` would spine a second, redundant copy), and `drop_preamble` (book-only default: `drop_root_preamble()` prunes the export root's loose preamble before the Doc build, so it can't surface as a spurious title-bearing chapter/page; overridable per export via `include_preamble`). Bibliographic metadata is also applied, but sourced from a root page's `guffin`-domain attributes (folded from a `guffin-meta::` block) rather than from the profile (so the profile's `title`/`authors`/`date`/`identifier` fields are currently unused); see `pandoc_rendering._document_metadata`. `abstract` is deferred indefinitely
    - `asset_fetch.py` — Pandoc-free asset fetching; `AssetRef` (UID + on-disk path + image pixel size (`None` for non-image assets) + original upload filename when known), the `fetch_asset()` primitive (fetch one `AssetVertex`'s Cloud Firestore asset to a local dir under its original upload filename, honoring a read-only mapping of already-claimed names), `fetch_assets()` / `fetch_and_enrich_assets()` (fetch a whole `VertexTree`'s image and PDF assets — tree and referenced vertices alike — coordinating name claims across the tree, returning `{uid: AssetRef}`; the enrich variant also populates each `ImageVertex.original_image_size` and `PdfVertex.original_file_name`), and `cover_image_path()` (pure lookup: the fetched local path of the cover image the root's `cover-image::` block ref names, resolved against a `fetch_assets` result)
    - `pandoc_ast.py` — Guffin-independent helpers for the Pandoc AST (the Panflute object model), with no dependency on the Guffin model: `InlineMap` (text→parsed-inlines mapping), `strip_links()` (unwrap every `Link` to its display text), `parse_inline_md()` (batch-parse Pandoc Markdown strings into inline element lists via a single Pandoc call), `parse_block_md()` (block-level parse preserving constructs like fenced code blocks), and `pandoc_to_json()` (serialize a Panflute `Doc` to a Pandoc JSON string, optionally dumping it to disk)
    - `pandoc_rendering.py` — shared Guffin-model→Pandoc rendering utilities (built on `pandoc_ast`); `vertex_tree_to_pandoc()` builds a Panflute `Doc` from a `VertexTree` (batch-parsing inline Pandoc Markdown via a single Pandoc call); a heading's `element-type`/`matter` tags stamp `epub:type` on the section header (via `epub_type_for`) and mark non-body-matter sections `unnumbered` so Pandoc's `--number-sections` numbers only body-matter chapters (a bare `matter::` tag overrides the element's default matter, logging any disagreement); the **tri-state effective-layout rules** (see `docs/render-pipeline.md`, *Children layout*) are applied per vertex on the way down the render recursion (`_effective_layout`, purely at the render layer and independent of the data source): a vertex's effective `children_layout` is its explicit `ViewMap` entry, else its parent's effective layout threaded down the recursion — for a transcluded tree the parent is the *embed vertex* that transcludes it, not its original host-page parent — else `DEFAULT_CHILDREN_LAYOUT` at the parentless root; `make_resolver(inline_map, daily_note_format)` builds the `VertexLinkResolver` that rewrites each `x-guffin` vertex link to its display inlines — a reference to a daily-note `PageVertex` (one carrying a `daily_note_date`) renders its date via `format_date` when `daily_note_format` is not `ROAM_LONG`, else falls through to the page title
    - `md_rendering.py` — renders a `VertexTree` to Markdown: invokes `pandoc_rendering`, serializes to Pandoc JSON, converts to GFM via Pandoc, writes a plain `.md` or `.mdbundle/` directory; the title renders as a leading H1 with all content headings demoted one level (clamped at H6) so the title contains them, and a title-page-emitting profile additionally serializes the document metadata as a YAML front-matter block (standalone GFM conversion) — with the entire content-revision summary joining it as a `revision` metadata entry; a non-front-matter profile (default) with an authored `revision::` name renders it as an emphasized `revision: <name>` line directly below the title H1 instead; the PDF title page mirrors this — an authored `revision::` name renders as an italic `revision: <name>` line directly below the title and in the running page header's right slot (replacing the publication date, which shows only when no revision is authored), all project types (Bergfink `revision` variable)
    - `pdf_rendering.py` — renders a `VertexTree` to PDF: invokes `pandoc_rendering`, serializes to Pandoc JSON, converts to PDF via Pandoc + Typst; PDF assets are **not** embedded in the output (matching the EPUB format) — an embed tagged `pdf-render:: inline` renders all of its pages in the document flow (one full-width Typst `image(page:)` per page — requires Typst ≥ 0.14), the untagged default rendering as the PDF's original filename in plain text with no link (`_prepare_pdf_embeds`/`_apply_pdf_embeds`, a post-build Doc rewrite of the PDF link paragraphs)
    - `epub_rendering.py` — renders a `VertexTree` to EPUB 3: invokes `pandoc_rendering`, serializes to Pandoc JSON, converts to EPUB via Pandoc (page title → `dc:title`, top-level headings → chapters, images embedded into the package), then runs `epub_post_processing.restore_matter_divisions()` on the packaged file — plus `stamp_titlepage_provenance()` when a colophon is emitted and the profile emits a title page (else the provenance renders as an end-of-document block, mirroring the PDF placement rules), and `stamp_titlepage_revision()` when a title page is emitted and the content authors a `revision::` name (colophon-independent, mirroring the PDF title page); without a title page (default type) the authored name instead leads the reading flow as the emphasized first body block

## Test Fixtures

Eight live Roam pages serve as the primary test sources: `[[Test Article]] 0`
through `[[Test Article]] 7`.  Each article exercises a distinct feature set —
see `tests/fixtures/README.md` for the per-article feature lists, which
`tests/regen_fixtures.py` keeps in sync from a callout on each live page.  For
each source, `tests/regen_fixtures.py` generates six fixture files that capture
different stages and views of the data pipeline.

### No-refs fixture set (`include_refs=False`) — a linear pipeline

Three fixtures representing successive stages of the export pipeline applied to
the anchor subtree alone, with no referenced pages included:

| Fixture | What it captures |
|---|---|
| `<prefix>_nodes.yaml` | The Roam nodes (page + blocks) as parsed `RoamNode` model objects |
| `<prefix>_vertices.yaml` | The same subtree transcribed into the export model (`VertexTree`) |
| `<prefix>_expected.md` | The fully rendered GFM output |

### With-refs fixture set (`include_refs=True`) — three views of the same fetch

Three fixtures derived from a single API call that pulls the anchor subtree
together with every page and block it references.  Rather than a pipeline, they
are three different lenses on the same underlying data:

| Fixture | What it captures |
|---|---|
| `<prefix>_raw_result.yaml` | The raw Datalog wire response before any `RoamNode` parsing |
| `<prefix>_anchor_tree.yaml` | The `NodeTree` of the anchor subtree itself (within the broader refs fetch) |
| `<prefix>_nodes_by_uid.yaml` | All fetched nodes — anchor subtree plus every referenced page/block — keyed by UID |

```bash
python tests/regen_fixtures.py "[[Test Article]] 3" --prefix test_article_3
python tests/regen_fixtures.py "[[Test Article]] 4" --prefix test_article_4
python tests/regen_fixtures.py "[[Test Article]] 5" --prefix test_article_5
python tests/regen_fixtures.py "[[Test Article]] 6" --prefix test_article_6

```

## Git
- **Never commit or push without explicit instructions**: do not run `git commit` or `git push` unless the user explicitly asks. This applies even after completing a task — finish the work, then wait for the user to request a commit/push.

## Conventions
- Src layout: package lives under `src/guffin/`
- Line length: 120 chars (Black + Ruff)
- Docstrings: PEP 257 format (pydocstringformatter), Google style convention (Ruff)
- **Dependent-agnostic documentation**: a module, class, or function must document what it offers on its own terms — never how its dependents (importers/callers) consume it. Don't name downstream modules or describe their usage in upstream docstrings or comments (e.g. avoid "X and Y delegate their logic here" or "shared by Z"); describe behaviour through the API's own parameters and contract, so the documentation reads identically regardless of who depends on it.
- **`Public symbols:` docstring is a by-kind index**: the module-docstring `Public symbols:` block is a *categorized index* of the module's public API, grouped by kind (pattern constants → type aliases → enums → models/classes → functions), with related symbols kept contiguous within a group. It is **independent of definition order** — the body's order follows define-before-use and feature cohesion (e.g. a discriminated-union alias must be defined after its members, a Typer `app` before the `main` it decorates), so the index and the body deliberately need not match. Keep the index grouping coherent; do not reorder code to track it.
- **Tests**: pytest, files named `test_*.py`. The `tests/` tree mirrors `src/guffin/`:
  each test module lives in the subpackage of the module it covers
  (`tests/<package>/test_<module>.py`, e.g. `tests/roam/test_markdown.py` for
  `guffin/roam/markdown.py`, `tests/common/test_markdown.py` for `guffin/common/markdown.py`).
  pytest runs in `importlib` import mode (`addopts = "--import-mode=importlib"`), so test
  files need no `__init__.py` and basenames may repeat across packages. `tests/conftest.py`
  and `tests/regen_fixtures.py` stay at the `tests/` root; shared non-fixture helpers are
  imported via `from conftest import ...` (`tests/` is on `pythonpath`).
- **Strong typing**: all Python code must use type annotations throughout; no `Any` types. Enforced on two levels: pyright in strict mode (semantic — every expression must resolve to a known type) and ruff's `ANN` ruleset (syntactic — parameter and return annotations must be written explicitly, not inferred). Local-variable annotations (see **Immutable bindings**) remain convention — no tool enforces them
- **Regular expressions**: use the third-party `regex` package **exclusively** — never the stdlib `re` module. Import as `import regex` and use `regex.compile`, `regex.Pattern[str]`, `regex.Match[str]`, `regex.DOTALL`, etc. `regex` is a drop-in superset of `re` (it defaults to `re`-compatible behaviour) and additionally supports recursive patterns (e.g. `(?R)` for matching balanced, nestable Roam page references). `types-regex` (a dev dependency) provides the stubs required by pyright strict mode.
- **Bash tool calls**: never chain multiple commands with `&&` in a single Bash tool call; use separate Bash tool calls instead. Never use heredoc embeds (`$(cat <<'EOF'...EOF)`) or ANSI-C quoting (`$'...'`) in Bash tool calls; both embed literal newlines in the command string, which prevents permission-pattern matching. For `git commit` messages that need multiple paragraphs, use repeated `-m` flags instead: `git commit -m "subject" -m "body" -m "Co-Authored-By: ..."` — each `-m` becomes a blank-line-separated paragraph.
- **Logging format**: all `logger.*()` calls must use `%`-style format strings (e.g., `logger.info("x=%s", x)`) — never f-strings (e.g., `logger.info(f"x={x}")`); this enables lazy interpolation and better log aggregation in monitoring tools.
- **`@validate_call`**: decorate every public function and method (non-`_`-prefixed, non-dunder) with `@validate_call`. Exceptions: `@property` methods (technically incompatible), Pydantic model lifecycle methods (`model_*`, field validators, `__init__`), CLI entry-point functions wired by argparse, methods overriding non-Pydantic framework interfaces, generic functions whose type variables cannot be resolved at runtime, and classmethods/staticmethods whose return-type annotation references the class being defined (pydantic eagerly evaluates type hints at decoration time, before the class is added to module globals, causing a `NameError`). For `@staticmethod` and `@classmethod` methods that qualify, `@validate_call` is placed innermost — just above `def`, below the `@staticmethod`/`@classmethod` line. When a function has panflute (or other arbitrary-type) parameters, use `@validate_call(config=ConfigDict(arbitrary_types_allowed=True))` instead of plain `@validate_call`.
- **Immutable bindings**: all local variables and module-level constants must be annotated `Final[T]` by default (e.g., `x: Final[int] = 1`, `MY_CONST: Final[str] = "value"`); only omit `Final` when the binding genuinely needs to be reassigned. Inside Pydantic models, use `ClassVar[T]` for class-level constants (Pydantic excludes these from model fields).
- **Side-effect-free functions**: side-effect-free functions are very highly valued — a function computes and returns a value; it must never mutate its arguments. State updates (dict inserts, accumulator writes) belong at the call site that owns the state. Declare read-only intent in signatures with abstract types (`Mapping` not `dict`, `Sequence` not `list`) for parameters that are only read, and name value-producing helpers as values (`_resolved_file_name`), not actions (`_claim_file_name`). Functions whose *purpose* is an effect (I/O, caching, rendering) are of course legitimate — keep effects there, at the edges, and out of computation helpers.
- **Parameter names**: function and method parameter names must be at least 3 characters long; single- and two-character names (e.g. `s`, `fn`, `cb`) are not allowed.

## Architecture
- **CLI isolation**: only modules in the `cli/` sub-package may import or use the Typer package (the entry points `export_roam_tree.py` / `dump_roam_tree.py` and CLI-only support modules such as `cli/params.py`). All modules outside `cli/` must be front-end agnostic so they can be used outside a CLI context without pulling in CLI dependencies. Within `cli/`, keep Typer out of modules that have a non-CLI reason to stay framework-free (e.g. `cli/common.py`, whose helpers are unit-tested directly).
- **Exit-point isolation**: all explicit process-exit calls (`typer.Exit`, `sys.exit`, etc.) must live exclusively in the CLI modules. Library code propagates exceptions; CLIs decide whether and how to exit. This keeps control-flow transparent and makes library code testable without mocking exit behaviour.
- **Semantic-vocabulary isolation**: `model/publishing_semantics.py` (`PublishingSemantics`/`PublishingAttribute`) and the modules it composes — the `model/attribute_anchor.py` anchoring affordances (`AttributeAnchor`/`TreePosition`) and the `model/chicago_structure.py` taxonomy its tag values come from (`Matter`/`StructuralElement`) — form a **format-independent vocabulary aligned with publishing-industry conventions**; none of them may ever depend on, or be named after, any output format. The affordance/taxonomy modules are deliberately separate from the vocabulary because what the model *can express* is independent of how the guffin vocabulary *chooses to use it*. Within `model/`, `chicago_structure.py` is a pure taxonomy at the **bottom of the conceptual stack** (no `guffin` dependencies) and `attribute_anchor.py` sits just above the primitives (depends only on `vertex.py`), while `publishing_semantics.py` sits at the **top**: it may depend on the structural primitives (`attribute.py`, `attribute_assignment.py`, `vertex.py`, `vertex_tree.py`), `attribute_anchor.py`, and `chicago_structure.py`, but none of those may depend on `publishing_semantics.py` — vocabulary-aware helpers (e.g. `find_publishing_attribute()`, `has_parts()`) therefore live in `publishing_semantics.py`, not on the primitives. Member names follow publishing labels, some deliberately diverging from format-specific terms (e.g. `table-of-contents`/`list-of-illustrations`, not EPUB SSV's `toc`/`loi`). Each per-format mapping (`StructuralElement → EpubType` in `render/epub_semantics.py`, and future `→ PDF`, `→ GFM`) lives in `render/` and is keyed on the enum member — never a name-equality lookup against a format's own vocabulary. See `docs/render-pipeline.md`.

## Modern Python Requirements (Python 3.14)
All code written or modified by Claude MUST follow these conventions — no exceptions:

- **Built-in generics**: always `list[x]`, `tuple[x, y]`, `dict[k, v]`, `set[x]` — never `List`, `Tuple`, `Dict`, `Set` from `typing`
- **Union syntax**: always `X | Y` and `X | None` — never `Union[X, Y]` or `Optional[X]`
- **Type aliases**: always `type Foo = ...` (PEP 695) — never `Foo: TypeAlias = ...` or bare `Foo = ...`. Exception: a shared **Typer parameter alias** (`Name = Annotated[T, typer.Option(...)]` / `typer.Argument(...)` reused across CLI commands, e.g. in `cli/params.py`) must use a plain assignment, because Typer reads the embedded `Option`/`Argument` metadata off the annotation object and cannot resolve it through a PEP 695 `TypeAliasType` (it raises `RuntimeError: Type not yet supported`).
- **No `from __future__ import annotations`**: not needed in Python 3.14 (PEP 649 deferred evaluation is the default)
- **No string-quoted forward references**: never `"ClassName"` in annotations; if a forward reference is needed, reorder definitions so the referenced name is declared first
- **No `cast()`**: never use `typing.cast()`; fix the type properly instead
- **No `Any`**: never use `typing.Any`; use a precise type or a type variable
- **Enum mixin subclasses**: always use the dedicated single-inheritance mixin — never mix a built-in type with `Enum`/`Flag` directly (Ruff `UP042`):
  - `class Foo(str, Enum)` → `class Foo(enum.StrEnum)`
  - `class Foo(int, Enum)` → `class Foo(enum.IntEnum)`
  - `class Foo(int, Flag)` → `class Foo(enum.IntFlag)`

- `GUFFIN_DUMP_PANDOC_AST` — set to any non-empty value to dump the Pandoc JSON AST to `<output-dir>/<target>.pandoc.json` before the Pandoc conversion step (`export-roam-tree`, all formats)
- `GUFFIN_INCLUDE_PREAMBLE` — backs the `--preamble/--no-preamble` flag (`export-roam-tree`, pdf/epub only); set truthy/falsy (e.g. `true`/`0`) to keep/drop the export root's loose preamble; unset, the `--type` profile decides (book drops, others keep)
- `GUFFIN_NUMBER_SECTIONS` — backs the `--numbering/--no-numbering` flag (`export-roam-tree`, pdf/epub only); set truthy/falsy to turn all heading numbering on/off; unset, the `--type` profile decides (book numbers, others don't)
- `GUFFIN_DAILY_NOTE_FORMAT` — backs the `--daily-note-format` flag (`export-roam-tree`, all formats); `roam-long` (default; a daily-note-page reference keeps the page's own verbose title, so output is unchanged), `iso` (renders those references as ISO 8601 dates), or `abbrev-month-day` (abbreviated month + day, no year, e.g. `Jan 1`)
- `GUFFIN_EMIT_COLOPHON` — backs the `--colophon/--no-colophon` flag (default on); set falsy (e.g. `0`) to omit the colophon (software provenance — source commit + export time — and content revision — snapshot hash + edit/fetch times + authored `revision::` name) from output (`export-roam-tree`, all formats). Placement differs by format: PDF renders it at the foot of the title page when one is emitted (Bergfink `titlepage-provenance`), else on a line below the running page footer (`footer-provenance`); EPUB mirrors the PDF rules — stamped at the foot of the generated title page when one is emitted (`epub_post_processing.stamp_titlepage_provenance`), else an end-of-document block; Markdown carries it as an end-of-document block. The test suite forces it off via an autouse conftest fixture so byte-for-byte fixtures stay stable
- `GUFFIN_DUMP_TYPST` — set to any non-empty value to dump the intermediate Typst sources `<output-dir>/<target>.body.typ` (bare body) and `<output-dir>/<target>.full.typ` (with template applied) for debugging (`export-roam-tree --format pdf`); no effect on the produced PDF
- `GUFFIN_PDF_CREATION_TIMESTAMP` — UNIX timestamp passed to Typst via Pandoc `--pdf-engine-opt=--creation-timestamp` to pin the PDF creation date for byte-reproducible output (`export-roam-tree --format pdf`); used by the live PDF fixture test
- `GUFFIN_LIVE_TESTS` — set to any non-empty value to enable live tests (e.g. `GUFFIN_LIVE_TESTS=1`); requires Roam Desktop running locally
